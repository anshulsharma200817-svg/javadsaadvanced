The Big Picture

Every problem starts with one question:

Can I solve this by making one decision?

If YES → Iteration / Greedy

If NO → Ask:

Do I need to explore multiple possibilities?

If YES → Recursion

Now comes the important part.

Step 1: Recursion

Recursion is not an algorithm.

It is simply a way to express a problem.

Example:

factorial(n)

depends on

factorial(n-1)

No choices.

Just one recursive call.

Tree:

factorial(5)
    |
factorial(4)
    |
factorial(3)

This is pure recursion.

Use it when:

Tree traversal
Factorial
Fibonacci (naive)
Linked list recursion
DFS

My Interview Decision Tree

Whenever I read a problem, I literally ask these questions:

1. Can I solve it with one local decision?
        ↓
      Greedy

2. Do I have to explore multiple choices?
        ↓
      Recursion

3. Do I need every possible answer?
        ↓
      Backtracking

4. Do the same states repeat?
        ↓
      DP

5. Am I finding an optimum (min/max/count)?
        ↓
      DP

6. Can I eliminate recursion?
        ↓
      Tabulation
One Last Mental Model

Think of recursion as the base engine.

                 Recursion
                      │
          ┌───────────┴───────────┐
          │                       │
   One recursive call      Multiple recursive calls
          │                       │
   Pure Recursion           Need all solutions?
                                    │
                           ┌────────┴────────┐
                           │                 │
                         Yes               No
                           │                 │
                    Backtracking      Do states repeat?
                                             │
                                      ┌──────┴──────┐
                                      │             │
                                     No           Yes
                                      │             │
                               Plain Recursion      DP
                                                     │
                                       ┌─────────────┴─────────────┐
                                       │                           │
                                 Memoization                 Tabulation

This is the architecture I wish every DSA course taught. Once you internalize it, you'll stop asking "Which technique should I use?" and instead derive the right approach from the problem's properties.
